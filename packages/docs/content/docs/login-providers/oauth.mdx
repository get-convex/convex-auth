The `oauth` component and supporting provider functions (`setupGoogle`,
`setupGithub`) allow your users to login via their existing Google or GitHub
accounts.

The steps below will guide you through configuring Google and/or GitHub
login. In the end, your Convex deployment will host HTTP routes for handling
the OAuth callbacks and redirect back to your application for handling the result.

<Callout type="info">
  Support for using other OAuth identity providers isn't included yet.
</Callout>

## Common setup

These steps are the same whichever provider you use. Install the `oauth`
component once per identity provider, so an app offering both Google and GitHub
login repeats the provider-specific steps below for each of them.

### Add a `users` table to the schema

Add an empty `users` table to your schema in `convex/schema.ts`.

Convex Auth will create a row for each account. You can also add application-specific fields to this table if necessary.

The table does not have to be called `users` — if yours has another name, pass
it to `setupCore`, and every provider's `attachUserCallbacks` will then require
callbacks typed with that table's ids:

```ts title="convex/auth.ts"
const core = setupCore({ component: components.auth, usersTable: "members" });
```

<Tab value="Google">

<Steps>

<Step>

**Register the OAuth app and its environment variables**

To allow users to login to your app via Google, you'll need to register an
OAuth application with Google.

<Callout type="info">
Follow the [Google OIDC
instructions](https://developers.google.com/identity/openid-connect/openid-connect#appsetup)
before proceeding.

Google will require you to provide a redirect URI when registering your
application.

The redirect URI will be based on your `CONVEX_SITE_URL`; something like
`https://happy-animal-123.convex.site/oauth/google/callback`. You can get your actual `CONVEX_SITE_URL` with this command:

```sh
npx convex env get CONVEX_SITE_URL
```

</Callout>

Google will assign a unique client ID and client secret to your application.
You will store those values as [environment
variables](https://docs.convex.dev/production/environment-variables#declaring)
on your Convex deployment.

Here are the Convex CLI commands to do that (you'll need to substitute your
actual client ID and client secret values):

```sh
npx convex env set AUTH_GOOGLE_CLIENT_ID <your-google-oauth-client-id>
npx convex env set AUTH_GOOGLE_CLIENT_SECRET <your-google-oauth-client-secret>
```

</Step>

<Step>

**Install the component**

Register an instance of the `oauth` component alongside the core in
`convex/convex.config.ts`. You will declare the environment variables that you
created above as part of your application's `env` and then pass those values to
the instance of the `oauth` provider.

<include
  lang="ts"
  meta='title="convex/convex.config.ts" highlight="import oauth from" highlight="app.use(oauth, {...});" highlight="AUTH_GOOGLE_CLIENT_ID:" highlight="AUTH_GOOGLE_CLIENT_SECRET:"'
>
  ../../../../../examples/react-google/convex/convex.config.ts
</include>

</Step>

<Step>

**Set up user creation**

Write a `createUser` mutation that creates a row in your `users` table and
returns its id. The provider calls it the first time it sees an account.

<include lang="ts" meta='title="convex/users.ts"'>
  ../../../../../examples/react-google/convex/users.ts
</include>

</Step>

<Step>

**Set up the public backend functions**

Set up the Google provider with `setupGoogle` and export the mutations for
starting and completing OAuth login that it hands back once you attach the
callback that creates your user rows, in `convex/auth.ts`:

<include
  lang="ts"
  meta='title="convex/auth.ts" highlight="import { setupGoogle }" highlight="export const { startSignInGoogle...}).attachUserCallbacks({ createUser: internal.users.createUser });"'
>
  ../../../../../examples/react-google/convex/auth.ts
</include>

Just like `createUser` is attached here, you can also attach an optional
`onSignIn` mutation, called with the resolved `userId` on every sign-in, the
first one included. Anything you want to happen each time someone signs in
belongs there, so `createUser` only has to handle what is true at creation
time. This example doesn't use it, but it's available if you need it.

</Step>

<Step>

**Set up the authentication UI**

In your front-end, install hooks and attach listeners for initiating OAuth login.

Include an `App.tsx` like the following in your application:
